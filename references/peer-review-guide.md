# Peer Review Guide

A structured evaluation checklist for reviewing UX case study briefs produced by this skill. Works for any phase (1-4). Designed for human reviewers, design faculty, or AI evaluators.

---

## How to Use This Guide

1. Read the brief once without scoring — get the overall impression
2. Walk through each section below, checking items as pass/partial/fail
3. Score the 4 dimensions at the end using the scoring rubric
4. Write 2-3 sentences of overall feedback focused on the weakest dimension

**Time needed:** 15-20 minutes per brief.

---

## Universal Checks (All Phases)

### Voice & Tone
- [ ] First-person plural ("we," "our") throughout — no third-person drift
- [ ] Past tense for research actions, present for findings, future-conditional for impacts
- [ ] Bolded phrases are 2-4 word noun concepts, not whole sentences or verbs
- [ ] No AI-prose tells: "delve," "navigate the complexities," "in today's fast-paced world," "comprehensive," "holistic," "robust" as filler
- [ ] Empathy without melodrama — difficulty is shown alongside resilience or meaning

### Evidence Standards
- [ ] Every numeric claim has a named, real source
- [ ] Statistics are paired (not solo, not triples) — reviewer can name the pairing logic (disparity+severity, belief+behavior, prevalence+cause)
- [ ] No fabricated numbers — spot-check 1-2 stats by searching the cited source
- [ ] Source quality is appropriate (government data, peer-reviewed, established research orgs preferred over blog aggregators)

### Visual Specifications
- [ ] Every section includes a "Visual elements to design" callout
- [ ] Chart types are named specifically (radar, donut, progress bar — not just "a chart")
- [ ] Icons are described with enough detail to commission (subject, style, context)
- [ ] Layout guidance is present (column count, relative positioning, emphasis hierarchy)

### Structural Integrity
- [ ] No standalone "Methodology" section — methodology is woven into narrative
- [ ] No solution leakage in Phases 1-3 (no product names, app descriptions, or specific implementations)
- [ ] Page breaks fall at logical boundaries
- [ ] Self-audit scores are present with one-sentence justifications per dimension

---

## Phase 1: Discovery Brief

### Funnel Narrowing (the critical check)
- [ ] Each section's subject is more specific than the previous
- [ ] Reviewer can trace the noun phrase narrowing: [global topic] > [national context] > [sub-group] > [individual voice] > [journey] > [synthesis] > [HMW]
- [ ] Write the noun phrases here: ______ > ______ > ______ > ______ > ______ > ______ > ______

### Page 1: Introduction
- [ ] Origin story present (how the team arrived at the topic, not just "here is the topic")
- [ ] "We conducted..." verb chain names specific methods
- [ ] Objective statement uses the formula: "design a [type] that addresses [need] of [user] and improves [outcome]"
- [ ] Length: 60-100 words across two paragraphs

### Page 1: Global Scenario
- [ ] 4-beat rhythm: acknowledge progress > pivot to problem > anchor in recency > visual evidence
- [ ] Problem cluster has exactly 2 named buckets with 4-6 labels each
- [ ] Bucket names telegraph the case study's eventual focus
- [ ] 2 hero statistics form a complementary pair (name the pair type: ____________)

### Page 2: National/Regional Perspective
- [ ] Comparative opener contrasts a better-off context with the target geography
- [ ] The contrast is honest, not strawmanned
- [ ] 2 stats: one belief stat + one behavior stat
- [ ] The belief-behavior pairing implicitly argues that cultural norms drive outcomes

### Page 2: Impact on Sub-group
- [ ] Causal claim narrows from national population to specific sub-group
- [ ] Constraining qualifier identifies a life phase or life moment, not just a demographic
- [ ] Evidence ladder: first stat compares sub-group to whole, second stat shows dominance within sub-group

### Page 2: Interview Insights
- [ ] Methodology opener names 3-4 perspectives interviewed (triangulation visible)
- [ ] 3 insight blocks cover 3 distinct flavors:
  - [ ] Operational/practical
  - [ ] Relational/social
  - [ ] Emotional/internal
- [ ] Each insight has a unique icon description and a bolded key phrase
- [ ] Pull quote is verbatim (not paraphrased) with attribution
- [ ] Attribution includes dual standing if applicable (expert + affected person)
- [ ] Closing nuance paragraph 1: related stakeholder's perspective
- [ ] Closing nuance paragraph 2: affected group's resilience or source of meaning
- [ ] Without these two paragraphs, flag as "missing nuance moves" — this is a common and serious omission

### Page 3: Emotional Arc
- [ ] Top caption describes scope and timeframe
- [ ] Scope disclaimer present ("Here we focus on [specific trajectory]") — explicitly states this is one path, not universal
- [ ] 5 chronological life-phase stages (labels are phases, not emotions)
- [ ] 8-12 touchpoints across the stages
- [ ] Curve zigzags — not monotonically ascending or descending
- [ ] Trajectory shape matches the research argument (descending zigzag = system fails through friction, etc.)
- [ ] Emoji indicators at each touchpoint
- [ ] 2-3 anchor icons at specific stages

### Page 4: Framework Section
- [ ] Named framework with 5-7 dimensions
- [ ] Framework matches the domain (wellbeing radar for health/social topics, alternatives for other domains)
- [ ] 1-2 focus dimensions explicitly named
- [ ] "Ripple effect" language present — admits scope limits while claiming reasonable breadth
- [ ] Visualization specified (radar/spider chart)

### Page 4: Opportunities
- [ ] Exactly 3 opportunity areas
- [ ] Each is a direction, NOT a solution (no product names, no "build an app")
- [ ] The 3 span different systemic layers:
  - [ ] Policy/structural
  - [ ] Community/social
  - [ ] Infrastructure/facilities
- [ ] Branching diagram specified in visual elements

### Page 4: Problem Statement & Expected Impact
- [ ] HMW follows the formula: "How might we help [life-phase user] [soft verb] [aspirational outcome with endurance word]?"
- [ ] HMW user is a life phase, not just a role or demographic
- [ ] "Why now" structural shift paragraph present below HMW
- [ ] 4 expected impacts that ripple outward:
  - [ ] Individual
  - [ ] Immediate relational (child, partner, etc.)
  - [ ] Family/work system
  - [ ] Societal
- [ ] Team credit line present

### Project State Block
- [ ] Present at end of document
- [ ] Includes: phase number, HMW, target user, geography, team, key artifacts
- [ ] Under 30 lines
- [ ] Usable as input for Phase 2

---

## Phase 2: Empathy Deepening

- [ ] Continuity checkpoint: restates HMW, target user, geography from Phase 1
- [ ] Filtration funnel present with 6+ stages
- [ ] Stakeholder map has 3 rings (CORE / INVOLVED / INFORMED) with 15+ entities
- [ ] 2 contrasting personas with different life circumstances
- [ ] Problem space mind-map with 5+ categories and 30+ sub-issues
- [ ] Experience map covers full user journey with touchpoints and pain points
- [ ] At least 2 invalidated assumptions with evidence
- [ ] New research added beyond Phase 1 (field visits, bodystorming, second-wave interviews)

---

## Phase 3: Problem Convergence

- [ ] Continuity checkpoint: restates HMW, target user, geography
- [ ] Problem scoring matrix with individual scores (or team-level rankings if solo)
- [ ] Clear narrowing rationale: why chosen problem won, why rejected ones lost
- [ ] Ecosystem map for the chosen problem with themes, needs, touchpoints, stakeholders
- [ ] Pain points documented (15+ for depth)
- [ ] Business viability section with market data and sources
- [ ] 3 sub-HMWs that break the main HMW into actionable angles
- [ ] Formal need statement following the "[User] needs [service] that [criteria] so that [outcome]" formula

---

## Phase 4: Solution Design

- [ ] Continuity checkpoint: restates HMW, target user, geography
- [ ] Cause & effect tree linking root causes to the central problem
- [ ] How-to questions across multiple angles (emotional, operational, cultural, safety)
- [ ] Solution has a name and clear identity
- [ ] 4-6 key features, each with a description of what it does and why
- [ ] Service flow with sequential steps
- [ ] Co-creation and testing methodology documented (N, method, materials)
- [ ] Validation data with percentages and sample sizes
- [ ] FAQs that explain mechanisms, not just restate features
- [ ] Framework return: connects back to Phase 1's framework dimensions
- [ ] Scalability axes (at least 2)
- [ ] No new problems introduced — solution addresses what was scoped in Phases 1-3

---

## Scoring Summary

After completing the checklist, score on the phase-specific 4 dimensions. Each phase has its own scoring benchmark in its reference file. The universal pattern:

| Dimension | Target | Red Flags |
|-----------|--------|-----------|
| AI-Likeness | 1-3 (lower is better) | Third-person drift, filler adjectives, missing nuance moves, bolded full sentences |
| Funnel/Structure Discipline | 8-10 | Same-scope sections, standalone methodology, no narrowing visible |
| Evidence Rigor | 8-10 | Unsourced stats, unpaired stats, fabricated numbers, vague attributions |
| Synthesis Sharpness | 8-10 | Broad HMW, solution-as-opportunity, flat impact list, missing scope disclaimer |

### Cross-Check Patterns

These combinations reveal problems individual scores might miss:

| Pattern | Diagnosis | Action |
|---------|-----------|--------|
| Low AI-Likeness + Low Evidence | Pretty prose, weak research | More desk research needed |
| High Funnel + Low Synthesis | Great narrative, vague landing | Tighten HMW and impacts |
| Low AI-Likeness + Low Funnel | Right voice, wrong structure | Restructure sections before editing prose |
| High Evidence + High AI-Likeness | Solid data, generic writing | Rewrite for voice without changing data |
